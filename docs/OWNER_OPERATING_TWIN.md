# Ferocity Owner Operating Twin

Ferocity should behave like a governed operational extension of the owner, not a generic chatbot or an undisclosed impersonator.

The first adaptive layer uses tenant-isolated Ask Ferocity history, explicit durable memories, current workspace evidence, authority rules, and verified action outcomes. It preserves recurring owner wording and predicts likely next commands. Suggestions are evidence-labeled and remain subject to the same approval, spending, messaging, publishing, contract, payment, and account-access controls as manually typed commands.

## Learning contract

- Learn from the owner's commands, corrections, accepted outcomes, and explicit preferences.
- Prefer patterns that led to completed Ferocity responses or verified action receipts.
- Preserve the owner's concise tone when suggesting a command.
- Never learn or reproduce passwords, tokens, payment credentials, private keys, government identifiers, or long financial/account numbers.
- Never convert repeated approval into permanent authority. Authority changes require the existing explicit authority workflow.
- Consequential suggestions are `draft_only`; one tap may submit the command for governed planning, but cannot bypass approval gates.
- Show confidence and why the suggestion appeared. Low-confidence predictions remain optional and cannot auto-run.
- Accept and dismiss feedback is scoped to the current tenant and current user. It expires after 365 days, is not exposed through browser database roles, and can be cleared without deleting chat or business records.
- Channel classification keeps internal commands, email, text, calls, vendors, and work orders distinct instead of learning one audience's voice for another.
- Every adaptive suggestion includes a deterministic key and an in-app evidence link. Evidence from another tenant is rejected before ranking.
- A deterministic daily owner brief summarizes current attention, opportunities, approvals, goals, and setup gaps from already-loaded workspace evidence. It does not use a model or claim that work is complete.
- Let the owner forget stored suggestion feedback and correct an active outcome using existing conversation controls.

## Next layers

1. Capture edit-distance feedback when an accepted suggestion is materially rewritten before submission.
2. Rank suggestions from verified business outcomes: collected revenue, completed jobs, response time, margin, reliability, and owner corrections.
3. Extend the same governed identity across Ferocity Connect, voice, email, MarketplacePro, and authorized portfolio integrations.

## Authority boundary

Suggestion feedback changes ranking only. It never authorizes sending, publishing, spending, payments, contracts, account changes, vendor commitments, work-order acceptance, or deletion. Consequential suggestions remain `draft_only` and enter the same governed command path as manually typed requests.
