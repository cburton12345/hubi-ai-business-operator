## Evidence rules

- `production verified`: the intended user completed the representative workflow against the deployed build and the durable result, source lineage, authority behavior, failure behavior, and continuation path were verified.
- `partially working`: meaningful runtime evidence exists, but the whole domain or its deployed/customer-facing path is incomplete or unverified.
- `broken`: current evidence demonstrates incorrect, misleading, unusable, or repeatedly failing behavior.
- `blocked by provider or owner-only action`: Ferocity-side setup is at its furthest truthful point and external approval, identity, payment, consent, or another genuinely owner-only step remains.
- Source presence, schema presence, a rendered page, a passing unit test, and a source-contract guard are supporting evidence only.
- Prior evidence is reused when it applies to the current build. Synthetic/local-only evidence is never silently promoted to production verification.

## Confirmed defects requiring repair

1. Deployed PDF runtime omits required `unpdf`/`pdfjs-dist` dependencies.
2. Structurally invalid empty primary/reviewer extractions can be labeled as agreement.
3. Allocation/reviewer usage can run after unusable extraction.
4. Historical document CTAs use current year rather than detected statement period/batch.
5. Deposit packets mix unrelated workspace statement transactions rather than proving source/batch completeness.
6. Expense packets omit statement debits when canonical `operations_expenses` records do not exist.
7. Production-generated dates use the wrong timezone and production can label itself `local`.
8. `run-business-automation-background` repeatedly crashes because of a `server-only` import in its standalone bundle.
9. Ask Ferocity can hide AI failure behind a generic successful-looking fallback.
10. Ask Ferocity's current 15-family capability enum and keyword execution do not represent the full platform.
11. Document conversation responses can bypass genuine reasoning and promise completion without validating extracted output.
12. Existing workflow-health/readiness checks do not reconcile deployed standalone-function health or full golden-loop completion.
13. POS returns create refund/ledger records and update sale state without reconciling the source invoice's `amount_paid_cents` and invoice status, leaving customer balance and accounting state inconsistent.
14. POS inventory-consumption and return movements record `unit_cost_cents=0`, so cost-of-goods and job-profit calculations cannot rely on those movements.
15. Purchase-order receiving can store a receipt with no matched inventory item and silently omit the stock movement/quantity update; the user is not given an unresolved-match state.
16. Vendor bills accept totals without deterministic reconciliation to purchase-order lines and quantities received, and the current accounting queue can imply QuickBooks work without proving an active reconciled provider connection.
17. The POS/inventory/purchasing suite contains four focused POS source tests but no end-to-end certification of sale -> invoice/payment/ledger -> stock/cost -> return/refund -> corrected invoice/margin or PO -> receive -> vendor bill -> job cost/accounting export.
18. Golden-loop certification can report all 13 stages certified after directly seeding already-completed synthetic records; it does not exercise the actual UI/actions/providers that transition the business through the loop.
19. Provider readiness reports Google/GBP, Meta, TikTok, Reddit, and Microsoft as configured while the credential-health audit is failing with eight expired access credentials and other rotation/inactive problems; configuration presence is being conflated with operational readiness.
20. Retell database state says callback `certified`, but the readiness check found no real inbound call, transcript, summary, duration, or call ID; transfer destination/tool are absent and outbound remains disabled.
21. Customer portal request/message submissions lack visible per-token rate limiting and idempotency, allowing accidental duplicates or abuse when a portal token is repeatedly submitted.
22. Membership visit generation decrements `visits_remaining` but does not exclude plans at zero, allowing additional visits after the promised count is exhausted once the prior visit is closed.
23. Public-chat-to-authenticated-workspace handoff failed role/order certification once and passed on immediate retry; the path needs repeated deterministic ordering and reliability coverage rather than being treated as conclusively stable.
24. A real December statement dual-model run took about 5.5 minutes and both models returned only the final-page subset. The existing merger treated a partially successful PDF as usable because it tracked transactions but not page-group failures. This is both a completeness defect and an impractical synchronous-upload latency path.
