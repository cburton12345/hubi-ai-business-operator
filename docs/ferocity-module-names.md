# Ferocity Module Names

Use simple owner-facing names first. Keep technical names in docs, routes, and admin details only when needed.

## Owner-Facing Names

| Use this name | Route | Meaning |
| --- | --- | --- |
| Daily Brief | `/app/ai-monitoring` | Morning owner summary and watchtower. |
| Today | `/app/attention-command` | The shortest do-this-now list. |
| Owner Command | `/app/owner-command-center` | Full owner event feed across Ferocity and connected systems. |
| Build My System | `/app/build-system` | Plain-English setup agent. |
| AI Workforce | `/app/ai-workforce` | AI employees and agent workflows. |
| Growth | `/app/growth-calendar` | Marketing, SEO, reviews, proof, website, campaigns, and attribution. |
| Leads | `/app/lead-command` | New leads, replies, callbacks, estimates, and follow-up. |
| Service | `/app/service-command` | Jobs, customers, estimates, invoices, dispatch, inventory, and reviews. |
| Workforce | `/app/operations-workforce` | Workers, crews, schedule, clock-ins, mileage, receipts, payroll review, and field proof. |
| Cash | `/app/cash-collection` | Open invoices, overdue follow-up, payment requests, payments received, and ledger visibility. |
| Safety | `/app/safety-readiness` | Provider keys, approvals, limits, launch blockers, billing, webhooks, and health. |
| Connected Systems | `/app/lifeops-connections` | External systems that send owner-level events into Ferocity. |

## Naming Rules

- Do not lead with internal phrases like "AI Monitoring & Briefing Center" when "Daily Brief" is enough.
- Do not make normal users choose between too many command centers.
- Use verbs and outcomes: watch, brief, follow up, collect, grow, review, connect.
- Keep routes stable even if visible labels change.
- Deeper technical descriptions can appear inside the page after the simple explanation.
